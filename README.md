## 👋 About

I'm a software engineer based in Bangkok who works **end to end** — the Flutter app in someone's hand, the API behind it, and the web dashboard the team uses to run it. Most of what I ship day to day lives inside a leasing company's IT systems, which means it has to survive real users, real money, and real audit trails. That constraint shaped how I write code: readable first, defensive where it counts, and boring in the places that matter.

Outside of work I build things I actually want to use — right now that's **[tunetrend](https://tunetrend.vercel.app/us)**, a music-trend app that ships as both a Flutter client and a live web app.

> **ภาษาไทย** — ผมเป็น Software Engineer อยู่กรุงเทพฯ ทำงานตั้งแต่หน้าบ้านถึงหลังบ้าน ทั้งแอป Flutter, API เบื้องหลัง และเว็บที่ทีมใช้งานจริง งานประจำอยู่ฝ่าย IT ของบริษัทลีสซิ่ง ซึ่งระบบต้องรองรับผู้ใช้จริงและเรื่องเงินจริง เลยให้ความสำคัญกับโค้ดที่อ่านง่าย ดูแลต่อได้ และไม่พังตอนตีสอง ส่วนเวลาว่างก็ทำโปรเจกต์ที่อยากใช้เองอย่าง tunetrend

## 🧭 How I Work

<table>
<tr>
<td width="33%" valign="top">

**🔍 Readable over clever**

Code is read far more often than it's written. If a reviewer needs a paragraph of explanation, the code is wrong — not the reviewer.

</td>
<td width="33%" valign="top">

**🛡️ Boring where it counts**

Money, auth and data migrations get the least surprising implementation available. Save the creativity for the UI.

</td>
<td width="33%" valign="top">

**📦 Small, shippable slices**

Short-lived branches, focused PRs, descriptive commits. Big-bang merges are where bugs hide.

</td>
</tr>
<tr>
<td valign="top">

**🌐 Localize from day one**

Retrofitting i18n costs three times as much. Every string goes through the localization layer from the first commit.

</td>
<td valign="top">

**📶 Assume the network fails**

Mobile users are on the BTS with one bar. Loading states, retries and offline handling are features, not polish.

</td>
<td valign="top">

**🤝 Leave it better**

Every PR is a chance to delete dead code, fix a confusing name, or add the test that was missing.

</td>
</tr>
</table>

> **แนวคิดการทำงาน** — เน้นโค้ดที่อ่านเข้าใจง่ายมากกว่าโค้ดที่ฉลาด, ส่วนที่เกี่ยวกับเงินและสิทธิ์ใช้วิธีที่ตรงไปตรงมาที่สุด, แตกงานเป็นชิ้นเล็กแล้วส่งบ่อย ๆ, ทำ localization ตั้งแต่วันแรก และออกแบบโดยคิดเสมอว่าเน็ตผู้ใช้จะหลุด
